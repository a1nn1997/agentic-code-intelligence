## Reported per stop clause

**Container-leak root fix:**
Every run gets a unique `--name acp-sandbox-<12hex>`. `_force_remove_container`
calls `docker stop --time 5 <name>` then `docker rm -f <name>` on timeout and
infra-error paths. proc.kill() alone is insufficient; the named-container path
is the source-level fix. Zero-leak proven by asserting `docker ps` count before
== after a forced-timeout run.

**Self-repair data-flow (how real sandbox output reaches model in DATA channel):**
`_do_verify` now stores `stdout_tail` + `stderr_tail` in the journal payload.
On verify failure, `_failure_text_from_journal` reads them from the durable
journal row. A `DataSpan(origin=sandbox_failure:step:<N>, content=<text>)` is
appended to `data_spans`; `build_channels(task.instruction, data_spans)` renders
it inside `<data><span origin="sandbox_failure:step:3">...</span></data>`.
The model sees it in `data_xml`; `instruction_xml` is unchanged. The stub reads
only `instruction_xml` for control flow — the failure text cannot escalate.

**Multi-file edit strategy + diff-check proving all call sites updated:**
`_do_rename` queries `index.definitions(old_name) + index.references_of(old_name)`
to discover all affected files. Whole-file `str.replace(old_name, new_name)` per
file. Content-addressed per artifact (apply-once gate). `_combined_patch` re-reads
worktree files for the sandbox envelope. Programmatic diff-check in
`test_rename_completeness_against_index_reference_set`: `missed = known_files −
patched_paths`; assert empty. Rename target: `serialize_user → serialize_user_v2`
across 4 Python files (1 definition + 3 callers + 1 test file).

**Concurrency conflict mechanism + no-lost-write proof:**
`commit_worktree`: (1) `fcntl.flock(LOCK_EX)` on `<workspace>/.commit.lock`;
(2) compare current DB `head_commit` to caller's `base_commit` — mismatch →
`ConflictError`; (3) equal → `shutil.copytree` worktree → base + advance
`head_commit`. Two concurrent threads (per-thread DB connections for SQLite
safety): exactly 1 success + 1 ConflictError, never 2 successes. Winner's file
in base; loser's not; `both_exist == False` asserted.

**Resume/apply-once/no-double-charge hold across repair steps:**
Simulated crash after repair EDIT step 4 is journaled but commit lost.
`_charge_from_journal` adds missing commit exactly once. Repair artifact appears
exactly once. Per-step commit counts = `{step: 1}` for every step. Terminal:
`verified_success`. Proven by `test_repair_edit_applied_exactly_once_across_resume`.
